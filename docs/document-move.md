# Перемещение документов

P1.1 добавляет одинаковую операцию перемещения для папок, сцен и заметок. Цель может быть папкой текущего проекта или корнем проекта.

## Контракт

`MoveDocument` содержит `command_id`, `document_id`, `parent_id` и `expected_revision`. TypeScript `ProjectPort.moveDocument` передаёт этот объект в Tauri-команду `move_document`; UI создаёт новый UUID команды для каждого подтверждённого перемещения.

## Гарантии Repository

- `BEGIN IMMEDIATE` сериализует запись; проверка `expected_revision` не позволяет молча перезаписать более новое состояние.
- Один SQLite commit обновляет `documents`, добавляет неизменённый текст в `versions`, журналирует `operations(kind='move')` и сохраняет сериализованный результат в `receipts`.
- Повтор с тем же `command_id` и тем же payload возвращает сохранённый результат без второго перемещения. Тот же ID с другим payload отклоняется как `CommandMismatch`.
- `parent_id` должен указывать на существующую папку этой же базы. Сцена, заметка и отсутствующий UUID отклоняются.
- Перемещаемый документ и целевая папка должны быть активными (`archived_at IS NULL`). Архивный документ нельзя переместить, а архивную папку нельзя выбрать как parent.
- Для папок recursive CTE запрещает назначить родителем саму папку или любого её потомка.
- Перемещение в текущее расположение является идемпотентным no-op: создаётся receipt, но revision и журнал операций не меняются.

WAL, `synchronous=FULL` и единая транзакция обеспечивают атомарность: после сбоя виден либо весь результат вместе с журналом и receipt, либо исходное состояние.

## UI

У каждой активной строки дерева есть действие «Переместить». Диалог строится через active-only `list`, показывает корень и доступные активные папки с полным путём; для перемещаемой папки её собственное поддерево скрыто. В отдельном списке архива действие недоступно. Перед открытием диалога редактор сохраняет черновик, чтобы revision в команде был актуальным. После успеха дерево возвращается в корень и обновляется; открытый документ остаётся выбранным с новой revision.

## Проверки

Rust-тесты покрывают перемещение в папку и корень, conflict guard, replay/mismatch receipt, atomic audit rows, чужой UUID, parent не-folder, циклы, архивный source и архивный parent. Component test проверяет выбор папки и полный IPC payload с revision и command ID.
