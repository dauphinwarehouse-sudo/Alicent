# ADR 0006 — Резервные копии, текстовые контрольные точки и формат v2

Статус: принято для очередного среза локального ядра.

## Решение

1. Копия создаётся нативным SQLite Backup API, а не копированием открытого `.sqlite3`. Пошаговая запись идёт во временный файл в выбранном каталоге; после проверки схемы, связей, целостности и соответствия текущего текста его версии файл синхронизируется и публикуется без перезаписи существующего имени. Копия самостоятельна, `journal_mode=DELETE`, расширение `.alicent-backup`. Файл не зашифрован.
2. Восстановление копии никогда не меняет существующую папку проекта. Read-only источник закрепляется в транзакции, копируется в staging, проверяется и при необходимости мигрирует там. Только затем новая UUID-папка становится проектом. Исходный `project.id` сохраняется: это другая копия того же проекта, не новая облачная идентичность.
3. Формат v2 добавляет `project.revision`, `checkpoints`, `checkpoint_documents` и триггеры ревизии проекта. Контрольная точка ссылается на неизменяемые версии сцен и заметок, не дублируя тексты. Она возвращает **только содержание**, не дерево, названия или метаданные; более новые документы остаются.
4. Предпросмотр читает метаданные постранично (до 200), а также глобальную ревизию проекта. Подтверждение возврата привязано к этой ревизии. Любая промежуточная запись документа делает подтверждение устаревшим.
5. Многодокументный возврат — одна `BEGIN IMMEDIATE` транзакция: автоматическая точка «Перед восстановлением», новые версии, тексты, FTS, журнал и идемпотентная квитанция. Ошибка или отмена до commit откатывает всё, включая точку отмены. Совпадающие тексты не создают лишних версий. Полный текст рукописи не материализуется в одном массиве: обрабатываются пары текстов по одному документу.
6. При открытии v1 сначала создаётся `backups/pre-migration-v1-<uuid>.alicent-backup`. Снимок и миграция относятся к одной read-транзакции: посторонний writer не позволяет повысить её до write и изменить неподкреплённые копией данные. Схема меняется транзакционно. Ошибка создания копии запрещает миграцию. Старое приложение не открывает v2; для возврата к старому бинарнику нужна сохранённая v1-копия, а не понижение схемы на месте.
7. Неизвестные версии или исполняемые SQL-объекты отклоняются. `trusted_schema=OFF` дополнен сравнением с известной схемой. Это консервативно: ручные пользовательские триггеры/изменения схемы не поддерживаются.
8. До операций UI принудительно сохраняет черновик, блокирует редактирование и закрытие во время работы. Копирование и возврат текста выполняются вне UI-потока, имеют отмену; интерфейс сообщает запрос отмены, не обещает отменить уже совершённый commit. Native file picker закрывается собственной кнопкой отмены. Обычная миграция при открытии пока не имеет отдельной кнопки отмены.

## Ограничения

- Чтение/проверка схемы и целостности не имеет отдельного progress handler; отмена проверяется на границах копирования и документов. Лимит копирования 300 секунд не является общим deadline всей проверки. Производительность очень больших баз не подтверждена.
- Последние несохранённые символы по-прежнему могут пропасть при убийстве процесса. Контрольные точки внутри той же базы не заменяют копию на другом физическом носителе.
- Не добавлены шифрование, scheduler копий, удаление старых версий, экспорт DOCX/Markdown или полноценный rollback дерева.
- Проверки путей запрещают symlink/junction-компоненты, но не устраняют все TOCTOU-гонки с враждебным локальным процессом. После аварии возможны скрытые staging-файлы; приложение не удаляет незнакомые файлы автоматически.
- Проверка импорта не доказывает подлинность/авторство резервной копии. Открывать следует доверенные файлы.

## Проверки

Rust integration tests проверяют живой backup с WAL, повторный импорт без замены оригинала, кириллицу/Unicode/FTS/версии/точки, отмену до публикации, уникальные имена, upgrade v1 с читаемой копией, запрет миграции без backup, неизвестные SQL-триггеры, аварийный выход дочернего процесса посреди DDL, optimistic conflict, атомарный rollback при ошибке второго документа, идемпотентность, автоматическую точку отмены и пагинацию.

Browser fixture проверяет flush перед точкой, обязательное подтверждение, возврат текста и точку отмены, запрет backup при ошибке сохранения, desktop light/dark и 390px. Это test-only IPC double, не проверка native file dialogs или установленного Windows приложения. Windows CI отдельно компилирует нативную оболочку и собирает unsigned installer.
