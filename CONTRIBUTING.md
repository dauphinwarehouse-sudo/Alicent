# Как вносить изменения

## Перед PR

Прогоните то же, что прогоняет CI:

```powershell
cargo fmt --all --check
cargo clippy --locked --all-targets -- -D warnings
cargo test --locked
npm run check
npm run test:ui
```

Если трогали `apps/desktop/src-tauri`, добавьте `cargo check --locked -p alicent-desktop`: этот крейт не входит в `default-members`, поэтому clippy и тесты его не собирают.

## Что обязательно в PR

- Тест на каждое исправленное поведение. Тест должен падать до исправления, иначе он ничего не доказывает.
- Запись в `CHANGELOG.md` в раздел Unreleased — о изменении для пользователя, не о рефакторинге.
- Изменили границу безопасности — обновите `docs/threat-model.md` и `docs/runtime-contracts.md` в том же PR, а не потом.
- Изменили формат проекта — новый `docs/project-format-vN.md`, миграция и тест на миграцию с предыдущей версии.
- Архитектурное решение — ADR в `docs/adr`.

## Утверждения и проверки

Правило из `docs/verification.md`: не пишите «проверено», если проверки не было. В описании PR разделяйте, что закрыто тестами и CI, а что только прочитано глазами. Незакрытое называйте незакрытым и оставляйте issue.

## Язык

- Код, имена, комментарии, сообщения коммитов и описания PR — по-английски.
- Документация в `docs`, тексты интерфейса и сообщения для пользователя — по-русски.
- Новые тексты для пользователя не зашивайте в доменные крейты. В `crates/domain` такие строки уже есть — это известный долг, а не пример для подражания.

## Коммиты

Conventional Commits: `fix(desktop): give every recovery operation its own cancel flag`. Тема в императиве и до ~72 символов, тело обясняет причину, а не пересказывает diff.

## Границы, которые не переступают без отдельного обсуждения

- Инструменты агента для массового create/move/delete: протокол одобрений и идемпотентность к этому пока не готовы.
- Сырой доступ к файловой системе из команд: запись идёт только через command layer с транзакцией и версией.
- Ослабление проверки провенанса промпта или разрешение записи для read-only политики.
